0/1 Knapsack DP

DP[i][c] = DP[i-1][c]            if w_i > c
DP[i][c] = max(DP[i-1][c],
               v_i + DP[i-1][c-w_i])  if w_i ≤ c

for i = 1..n:
  for c = 0..C:
    dp[i][c] = dp[i-1][c]
    if w[i] <= c:
      dp[i][c] = max(dp[i][c],
                     v[i] + dp[i-1][c-w[i]])
backtrack from dp[n][C] to list items

This site extends the table to two limits, time and budget: dp[i][t][b], costing O(n·T·B).

Dijkstra

dist[all] = ∞;  dist[s] = 0
pq = [(0, s)]
while pq not empty:
  (d, u) = extract_min(pq)
  if d != dist[u]: continue
  for each edge (u, v, w):
    if dist[u] + w < dist[v]:
      dist[v] = dist[u] + w
      parent[v] = u
      push (dist[v], v)

Valid only for non-negative edge weights. Unreachable nodes keep distance ∞.

Greedy ranking

sort attractions by value / duration (desc)
used = 0
for each attraction a:
  if used + a.d ≤ capacity
     and cost + a.c ≤ budget:
    choose a

Quick, but the best ratio first can block a better combination, so it is not guaranteed optimal for 0/1 choices.

NP-CompleteIn NP and NP-HardDecision versions of Knapsack and TSP variants

Reduction: Knapsack ≤p Simplified Attraction Selection. Make one attraction per Knapsack item with value vi and duration wi, set all travel costs to zero, remove time windows, and set capacity C. The answer is YES exactly when the Knapsack instance is YES, so the simplified problem is NP-Hard, and NP-Complete as a decision problem.

Knapsack DP is pseudo-polynomial: its running time depends on the numeric size of the capacity, not just the number of bits needed to write it.
