Report summary

A short version of the project report.

Abstract

The system helps travellers build practical itineraries within a limited budget and time. It treats attraction choice as a selection problem and road travel as a weighted graph. Greedy methods give a quick schedule, 0/1 Knapsack dynamic programming chooses a high-value subset, and Dijkstra’s algorithm finds shortest routes. No single algorithm solves every part optimally, so a hybrid design balances solution quality, runtime and implementation effort.

Objectives

  • Represent attractions by value, cost, duration and opening time.
  • Select a high-value subset within time and budget.
  • Model roads as a weighted graph and compute shortest paths.
  • Compare greedy, DP, graph and search approaches.
  • Validate with at least five test cases.
  • Explain why exact optimisation is hard.

Problem statement

Input: attractions with value vi, cost ci, duration di; a graph G = (V, E); start s; time H; budget B.

Output: a selected set S, an ordered itinerary, routes and totals.

Constraints: Σci ≤ B and Σdi + travel ≤ H.

Objective: maximise Σvi.

Advantages

  • Selection and routing in one framework.
  • Respects both time and budget.
  • Uses well-studied algorithms with known complexity.
  • Explainable output.

Limitations

  • Travel times change with traffic and crowds.
  • Opening hours add state and complexity.
  • Exact route ordering is exponential for many stops.
  • This is an educational prototype.

Future enhancements

  • Real map and transit APIs.
  • Opening hours, lunch breaks, reservations.
  • Multi-objective optimisation.
  • Local search or approximation for large instances.

Conclusion

Greedy gives speed, Knapsack DP gives optimal selection for the modelled limits, Dijkstra gives optimal shortest paths for non-negative weights, and search handles small exact cases. A hybrid planner that validates every candidate against both selection and route constraints is the recommended design.
